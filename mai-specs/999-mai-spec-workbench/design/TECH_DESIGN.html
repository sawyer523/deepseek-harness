SDD 工作台只读插件

为 DeepSeek Harness 提供两个只读模型工具，把 my-ai-infra 的 mai-specs/ 工作区结构直接暴露给会话中的模型：一次调用完成 Feature 导航与验收摘要，一次调用按语义入口读取规格文档。

设计原则 整体架构 数据结构与解析 数据流程 变更文件与核心代码 方案小结

route设计原则

  • 最小侵入：全部新增在仓库根 plugins/mai-spec-workbench/，不入 pnpm workspace、不改 packages/；既有代码零修改（仅 .gitignore 追加一行忽略本机生成的 overlay）。
  • 复用执行世界：文件访问一律经 ctx.fs（本地/沙箱/SSH provider 一致），会话目录用 ctx.workingDirectory.ensure(exec.agent)，取消透传 exec.signal。
  • 只读：两个工具只调用 resolve / stat / listDir / readText，不写不删。
  • 配置失败要响：项目级 FEATURE_LAYOUT.json 存在但损坏时整体报错指明文件，绝不静默回退默认路径。
  • 单点宽容：单个 Feature 的 BRIEF 解析失败不中断列表，以 phase: "unknown" 与警告如实呈现；验收摘要只报计数与缺省态，不伪造整体通过结论。

account_tree整体架构

插件经 setup.mjs 生成的 overlay（绝对路径行）由 dsh --patch 插入组合树；工具注册即 effect，随插件卸载自动反注册。

schema数据结构与解析

无数据库；核心是三组纯函数产出的内存结构（与工具 canonical 输出同形）：

结构 / 函数来源关键规则
FeatureBriefBRIEF.md：标题行 # {id}: {title} + 两列表格仅取 Phase / Profile / 优先级 三个键；字段缺失保持 undefined，不抛错
AcceptanceSummaryTEST_PLAN.md 的 ## 执行结果 节表格按「结果」列计数 通过/失败/未执行/受阻/待核验，未知值并入「其他」；节缺失或无数据行 → no-results；无 TEST_PLAN → no-test-plan
SpecWindowwindowLines(text, offset, limit)1-based 行号窗口；单次最多 2000 行、单行超 2000 字符截断加省略标记；offset 越界返回空窗口但 totalLines 如实
artifactPaths(layout)内置默认映射 + FEATURE_LAYOUT.json 覆盖version !== 1、JSON 损坏或 artifacts 缺失 → 整体报错；契约未登记的产物沿用默认路径；brief 恒为 BRIEF.md

Feature 目录判定：/^\d{3}-/（NNN-slug），列表按目录名升序；读取时目录名全等或纯三位编号前缀匹配（编号全局唯一）。

工具骨架（src/index.ts，拟议代码）

export const name = 'mai-spec-workbench'
export const inject = ['tools', 'fs', 'workingDirectory']  // dsh-base 提供三个服务

export function apply(ctx: Context): void {
  ctx.tools.register(defineTool({
    name: 'mai_features',
    parameters: {},                       // 无参数
    async execute(_args, exec) {
      const cwd = await ctx.workingDirectory.ensure(exec.agent, exec.signal)
      const root = await ctx.fs.resolve('mai-specs', { cwd, signal: exec.signal })
      if (await ctx.fs.stat(root, exec.signal) === undefined)
        throw new MaiWorkbenchError('notFound', `no mai-specs/ directory under "${cwd}"; run "mai init" first`)
      const layout = await readLayoutIfPresent(ctx, root, exec.signal)  // 损坏即抛
      // 扫描 NNN-slug 目录 → BRIEF/产物/验收摘要 → canonical JSON（单 Feature 宽容）
    },
  }))
  ctx.tools.register(defineTool({
    name: 'mai_spec_read',
    parameters: {
      feature: { type: 'string', required: true },   // "999" 或 "999-mai-spec-workbench"
      artifact: { type: 'string', required: true, enum: ['brief', 'prd', 'design', 'test-plan', 'design-review', 'code-review'] },
      offset: { type: 'number' },                    // 默认 1
      limit: { type: 'number' },                     // 默认/上限 2000
    },
    // 目录唯一匹配 → 契约路径 stat → readText → 行窗口 canonical 输出
  }))
}

task_alt方案小结

本次交付一个零侵入的 out-of-tree 只读插件：两个模型工具把 mai-specs/ 的结构化事实（Feature 阶段、产物状态、验收计数）一次调用暴露给会话，替代此前的多跳通用文件工具翻找。最关键的取舍是解析与产物契约全部做成不依赖框架的纯函数（可直接单测），以及"布局损坏即失败、单 Feature 异常即降级"的失败语义——汇总工具不伪造证据，缺什么就如实报什么。
